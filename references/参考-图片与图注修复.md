# 参考-图片与图注修复

> 适用场景：从 MinerU 解析源 md 抽题录入时，出现「图注丢失 / 空 alt / 图片本体缺失 / 孤儿图配对」等问题的定位与修复。
> 依据 2026-09-19「河南《解析与检测》2026 下册综合检测 8 套」录入实测沉淀；示例中路径均为占位符，实际以当次会话临时目录为准。

## 一、polish 图注删除机制与空行躲避法

**问题形态**：pass2 JSON 题干里明明有图注文字行（如「贾湖骨笛\n河南出土\n距今 8 000 多年」），build 后入库笔记里却消失。

**根因**：build 侧选择题题干清洗函数 `polish_choice_stem` 会删除「图注/年代注释残留行」，删除条件为**全部满足**：

1. 行非空
2. 不含图片语法 `![`
3. 不含作答括号 P
4. 非表格行（不以 `|` 开头/结尾）
5. `len(st) <= 24`
6. **上一行是图片行**（`out[-1]` 含 `![`）

**躲避法**：在 pass2 中把「图片行\n图注行」改为「**图片行\n空行\n图注行**」——处理图注行时 `out[-1]` 是空行，条件 6 不满足，图注行存活。空行随后被 polish 第③步清理，最终题干无空行，不影响成品。

**连带效应**（利用而非规避）：
- 图注行与作答括号同行（如「残存的圆明园文渊阁藏《四库全书》（　　）」）时，条件 3 已使其天然存活，无需处理；
- polish 第③步「删除所有 P → 末行后补 P（末行是图片/表格/占位说明则另起一行）」会自动把 P 安放到正确位置，定点替换时 P 可交给 polish 处理。

**定点修复范式**（幂等：重复执行结果不变）：

1. 源 md 建立哈希→alt 映射：`re.findall(r'!\[([^\]]*)\]\(images/([a-f0-9]{64})\.(?:jpg|...)\)')`
2. 全局补全：pass2 各字段空 alt `![](images/哈希)` → `![alt](images/哈希)`，**跳过无信息 alt**（空 / 「图片」 / 「image」）
3. 定点替换：按 (卷, 题) 定位，正则按「alt 已补形态」书写；散行图注合并成一行完整图注（如「贾湖骨笛（河南出土，距今 8 000 多年）」）+ 空行分隔
4. 图片行后插空行：仅对目标题逐行处理（图片行且下一行非空 → 插空行）
5. 幂等保障：运行前备份 pass2 到独立子目录；替换未命中时若「已修复形态已在文中」则静默跳过、否则报错中止；重跑零改动
6. ⚠ 替换串里的 CDN 来源图哈希不在源 md 本地映射中，需写死完整哈希（与本地 images/ 核对后），不能依赖映射反查

**CDN 嵌选项的配图题**（如「图+A.《作品》+图+B.《作品》…」交替结构）：图片语法嵌在 pass2 选项字段内，图片顺序与选项字母序天然对应。build 检出选项含图片即**改出 md 表格**（第一行图片、第二行 `A. 文字`，见 `references/试卷排版规范.md` §10.2.1）——**无需手工修复**，build 后抽查即可。

## 二、图片字段空 alt 机制

**机制**：`qb_schema.build_body` 对 `rec["图片"]` 字段的图**硬编码空 alt**（`![](images/name)`）追加到正文尾部；题干中已有的同名引用才去重跳过。

**推论**：
- 题干内的图片行**原样透传**（alt 保留）→ 有信息的 alt 必须补在 **pass2 题干文本内**，补在别处无效；
- 「图片字段来源」的图（pass2 里只有哈希列表、不在题干文本中）走 build_body 硬编码路径 → **alt 必然为空**，gen JSON 中无 alt 位可填。

**兜底**：入库后对 TNote 笔记文件直改——用源 md 哈希→alt 映射，把 `![](images/<哈希>.jpg)` 替换为 `![alt](images/<哈希>.jpg)`（Obsidian 运行中自动索引）。数量通常个位数，一次性脚本即可。

**待改进项**：`build_body` 支持 `{"src","name","alt"}` 三键（alt 缺省空）；`step10_build` 生成图片字段时从源映射传入 alt。改动涉及 skill 共享脚本，启用前需评估影响面。

**规模化实测（2026-09-19，全系列 10 套）**：「图片字段来源」空 alt 的量级是 **40 处/10 套**（远超"个位数"预估），按映射可补性三类处置：
- **可补（实测 8 处）**：上册（顺序命名图如 `1_1.jpg`）走**三级映射**：库内文件内容 MD5 → 源 images 同内容文件的哈希名 → 源 md alt；下册（哈希命名图）文件名直查源 md alt。
- **无信息保留（实测 31 处）**：源引用为 CDN 且 alt=image、或源 alt=「图片」——源头无信息，不补，巡检报告单列。
- **错配过滤**：MinerU 会把**版面结构标题**错配成图片 alt（实测：上册卷2/20 联合国海报图源 alt 为「非选择题(共5小题,30分)」，图正确、alt 错配）——建映射须过滤结构文字（如 `(非)?选择题|共\d+小题`），可疑项目检后再定。

**映射三坑（2026-09-19 实测）**：
1. alt 映射的 key 是 MinerU **哈希文件名**，不是文件内容 MD5——上册顺序命名图拿 MD5 直查必落空；
2. 源 md 图片有**三形态**：本地 `![alt](images/HASH.jpg)`、CDN `![alt](https://cdn-mineru…/HASH.jpg)`、**HTML `<img src="images/HASH.jpg"/>紧跟文字`**（表格内，alt=标签后至 `</td>` 前的文字，实测上册卷1/22 材料一）——建映射须三形态同抓；
3. 库内图在源 md 可能**仅以 CDN 形态被引用**（本地/CDN 引用混用），只按本地图建映射会漏。

## 三、孤儿图统计的 CDN 前缀坑

**背景**：MinerU 输出的 images/ 目录常多于源 md 引用数，需要统计「未被引用的孤儿图」以评估缺图能否配对回填。

**坑**：源 md 中图片有两种引用形式：
- 本地：`![alt](images/<64字符>.jpg)`——文件名实为 **60 位 hex + 4 位序号**（共 64 字符）；
- CDN：`![image](https://cdn-mineru.openxlab.org.cn/result/<task>/<64字符>.jpg)`——URL 末段**带 `.jpg` 扩展名**，alt 全为无信息的「image」。

⚠ 直接对 URL 末段套 `[a-f0-9]{64}\)` 或固定长度 hex 正则会因 `.jpg` 后缀漏匹配 → **CDN 图的本地副本全部被误判为孤儿**（实测 41 张中 19 张误判）。

**正确姿势**：抓完整 URL → `os.path.basename` → 从 basename 中 `re.search(r'([a-f0-9]{40,64})')` 提取 hex 段 → 加入 used 集合 → 本地文件名 `startswith(hex段)` 判定引用。

**孤儿图构成的经验判断**：MinerU 对表格区域常**同时输出 HTML 表格与表格截图副本**，md 只引用 HTML 形式 → 孤儿图多为表格/年代尺/文字截图。**配对实物照片前先看孤儿构成**（生成缩略拼贴目检），避免无效配对。

**MinerU vlm 漏检定性**：若某题在源 md 中只有图注文字行、图片块完全缺失（本地图与 CDN URL 均无），且 pass1/pass2 亦无图片引用，则根因 = **MinerU 解析阶段漏检**（识别到图注但未输出图片块）。重新解析可能复现漏检且需重跑全链路；题干文字自含作答信息时，接受现状是合理决策（定性结论记入日志）。

## 五、排版巡检与空行修复（2026-09-19 全系列实测沉淀）

**巡检脚本双正则铁律**：md 图片语法 `![alt](path)` 与 wikilink `![[name]]` **必须双正则同查**——`![[...]]` 不匹配 md 图片正则，只查一种时「图文同段 / 图注紧贴 / 上下文粘连」全部漏报（实测：wikilink 图行与图注同行粘连 2 处、与选项同行 1 处，脚本零报告，人工抽查才抓到）。另：wikilink 裸文件名引用可被 Obsidian 全库按文件名解析（含跨卷借用他卷 images 的图），**不是硬断链**，但迁移/导出/脚本处理会断，巡检报告应单列提示。

**图组并排保护**：md 里**连续图片行**（`图1行\n图2行\n图3行`）与**一行多图**渲染为横向并排——可能是刻意的「多图并排」实现（河南卷图组题式样）。插空行修复必须白名单保护：**图片行只与「非图片行」补空行，连续图行之间不插**；表格行内嵌图不动（在表格布局内，插空行会破坏表格结构）。

**空行修复幂等范式**：图片行的上一行非空且非图片行 → 行前插空行；下一行非空且非图片行 → 行后插空行；YAML 与代码块跳过。修复后固定三验：①重跑巡检（粘连类归零）②幂等复跑（零改动；注意先跑拆行再跑插空行时，拆行的「已修复形态」判定须按粘连特征而非整串匹配，否则被插行后的文本不再命中）③`scan_questions.py` 全量校验。修改前按相对路径备份原文件到工作区 tmp。

## 六、PPT 讲解件（试卷评讲 pptx / 其导出 PDF）图片处理定式（2026-10-04 立）

**源型识别**：源为「试卷讲解PPT」（pptx，或由其导出的 PDF，页面为 960×540 幻灯片尺寸）。此类文件的图片是**幻灯片截图**——照片/图形与图注艺术字烘焙进同一张 PNG（PPT `ppt/media/` 里同样是合成图、alpha 全不透明），**没有更干净的源**；导出 PDF 后黑底照样在。正文有文字层，走链路B 直读免 MinerU，但**图片必须逐张改造**。

**判据一：反相前先判原图底色（血泪教训）**——先算原图的 `mean`：**`>130` 即白底，切勿反相**（反相会把白底压成黑底）。实测两例（试卷7 第 18 题淝水之战图、试卷8 第 22 题三幅形势图）原图本是白底，被误判为黑底做了反相，反而弄脏。辅证判据：图像**四边 3px 的平均亮度 >100** 即白底；**只用 `mean` 会漏判**（器物偏亮时 mean 高达 165 仍是黑底），故识别黑底用「四边亮度」，定性白/黑用 `mean`。

**判据二：三类图分开处理**

| 图类 | 判据 | 处理 |
|---|---|---|
| **实物照片**（器物 / 文物 / 钱币 / 农具） | 内容有色彩或连续灰阶 | **只刷背景、不反相**：`mask=(gray<th)` → `cv2.connectedComponents` → 取**触及四边**的 label 作背景 → `rgb[bg]=255`，器物原色不动。⚠ `th=55`；整张反相会让照片变**负片** |
| **示意图 / 地图 / 时间轴**（黑底白线） | 内容为纯白线条与文字 | **整张标准反相** `255-a`。⚠ **禁用"抬黑反相"**（`60+(255-a)*195/255`）——它把线条压成深灰 #3C，打印发虚（用户定性为「文字变淡变模糊」）；标准反相后 `mean` 达 222~240，线条纯黑 |
| **纯文字图**（AI 对话框、清单、文字型示意图） | 内容 100% 是文字、无图形信息 | **不保留图片**：把文字搬进正文，删除图片文件 |

**多图一律裁开、上图下文重组**：含多幅子图的（多件文物、多张地图、照片＋地图混排）先按**列空白区**切分——连续满足 `列前景占比 < max(0.008, 1/H*1.1)` 且宽度够的区间即切点；切不动时（如三幅紧密并排的白底地图）在预期位置邻域取「最空列」。再逐张按所属类别处理：**混排图按性质分头处理**（如「秦朝刑具照片＋征役形势图」→ 照片刷背景、地图反相，避免照片变负片）。重组后的正文一律 md 表格（第一行图片、第二行图注），写法见 `references/试卷排版规范.md` §10.2.1。

**图注处理**：图内的图注艺术字在裁切时一并去除，**改写到表格第二行**（写法见 `references/试卷排版规范.md` §10.2.1）；而**图片自带的素材说明**（如钱币图旁的「汉初四铢半两钱，汉文帝时始铸……」）属**素材内容**，不删。

**三类"看着黑"但不可处理**：① **拓片**（黑底白字是内容本体）；② **深色青铜器**（器物固有深色）；③ **地图细黑边框**。一律保留。

**实测（2026-10-04，七上期末三卷，50→53 张图）**：36 张实物图刷背景、9 张示意图标准反相、4 组多图裁开、2 处纯文字图正文文字化；结果 **断链 0 / 孤儿图 0 / `scan_questions.py` ✓ 无问题**。

**实测记录（2026-09-19 全系列 10 套 A-C 修复）**：定点拆行 2、补 alt 8（无信息保留 31）、插空行 66 处/30 文件；修复后图文粘连三类归零、scan ✓ 无问题；被改文件备份于工作区 tmp 备份目录。

## 七、网络补图（低质图 → 开放图库候选，2026-10-09 立，2026-11-07 修订）

**场景**：扫描卷裁出的图过小/过糊，想换高清版。2026-11-07 全库复测：**严格档 319 张**（265 张有图注可作检索词，54 张无图注无从检索），集中于七上/七下（中国古代史器物）与郑州、洛阳各区期末卷。

**前提：库内互补这条路不通**（2026-11-07 实测）——1512 张带图注图片中，跨卷同图注仅 71 组（4.7%），其中尺寸差 ≥4 倍仅 **11 组（0.7%）**。同名器物在不同卷多为同一张扫描图，指望「A 卷糊了借 B 卷的」几乎无效，只能外部补图。

**工具**：`scripts/find_better_images.py`（**只读辅助，不自动替换**）

| 能力 | 用法 | 要点 |
|---|---|---|
| ① 筛查 | `--卷 <卷名>` / `--全库` [`--门槛 严格\|宽松`] | 列出低质图，附卷/题号/**图注**（图注即天然检索词）；严格＝短边<120px 或 总像素<4 万 |
| ② 检索 | `--查 <词>` / `--查表 <文件>` | 查 Wikimedia Commons。**已内置 `filetype:bitmap`**、候选按面积降序、`--最小边` 设最小短边、查表行第三段可写原图尺寸（`贾湖骨笛 \| Jiahu bone flute \| 232x146`）→ 只留 ≥`--倍率`（默认 1.5）面积的候选 |
| ③ 分类 | `--分类 "Longmen Grottoes"` | 直列某 Category 成员文件；分类下无文件时自动列子分类名 |
| ④ 留痕 | `--卷 <卷名> --留痕` | **录入关口的标准调用**：自动定位卷目录写 `_图片体检.md`（含「判定／依据」列与四值口径）；无低质图时不生成。见 `workflow/01-input.md` 铁律 7 |
| 限流 | `--间隔`（默认 **2.5s**）/ `--重试`（默认 3，退避 2×4×6×） | UA 已按 Wikimedia 要求带联系方式 |

**可用范围（两轮实测判定）**：

| 类别 | 是否可换 | 说明 |
|---|---|---|
| 著名文物/器物照片、名画书影、历史地图、人物肖像 | ✅ 可换 | 常能拿到 1500~7900px 的 PD/CC0/CC BY-SA（实测贾湖骨笛 4752×3168 CC0、妇好鸮尊 5158×7734、人面鱼纹彩陶盆 7641×5097） |
| 地方性文物（特定出土器物、地方墓葬壁画） | ⚠ 多半无解 | 同名易是「异地同类」；但**河南博物院、殷墟、龙门**一类有系统性拍摄上传，命中反而好 |
| 中国近现代照片（条约、会议、战争、建设场景） | ⚠ 有图但质量参差 | 见下「近现代照片渠道排序」——老照片固有分辨率上限 400~1000px，错配率也高 |
| 原卷原创示意图/流程图、统计数据图表 | ❌ 禁止换 | 命题者特制，换了破坏题目 |

**实测规律**（2026-10-09 立，2026-11-07 补充为五条）：

1. **中英双轨、别只押英文**——应县木塔／宋代蹴鞠铜镜／神舟五号由英文词命中；但**也有反向案例**：人面鱼纹彩陶盆英文全返回 PDF 垃圾、中文出 7641×5097 巨图。双轨都跑。
2. **中文裸查陷阱（2026-11-07 新）**——中文词裸查会被 CADAL 批量上传的 djvu/pdf 古籍扫描淹没，中文分词差还导致单字误命中（「杜岭方鼎」→「杜骗新书」「杜少陵全集」）。**`gsrsearch` 追加 `filetype:bitmap` 后噪声清零**：同一词从 3 个 djvu 变成 3 张 1800×1200 器物照。脚本已内置，勿删。
3. **相关性排序弱（2026-11-07 新）**——全文检索会返回只沾边词的文件（查「Water and Land Battle bronze hu」返回山彪1号墓空首布）。脚本对**英文词**给「相关」列（`⚠ 弱` ＝文件名不含检索词、须重点核对）；纯中文词检索到的多为英文命名文件，该列显示 `—` 属正常。
4. **同名不同物是最大风险**——同名会返回同塔不同角度、异地同类器物（实测禹州宋墓壁画 → 登封宋墓壁画）；**候选必须人工确认是否为同一件**，确认不了保留原图。
5. **两个技术坑**——429 限流：间隔 1.5s 时实测 30 次查询 7 次失败（23%），**默认已提到 2.5s**（实测转 0 失败）；SSL 握手超时偶发，靠退避重试兜住。
6. **换前比「形制」，不能只比名称**（2026-11-07 实测）——① **术语要用对**：元代符牌在 Commons 的正确检索词是 **paiza**（西方学界用词），中文「符牌／金牌」零命中；近现代照片用**旧拼**（Nanking/Peking/Canton）。② 术语对了还要比**外形轮廓、环孔位置、中央纹饰、环绕文字**是否一致——实测原卷为**桃形**符牌，Commons 上最接近的两件（内蒙古博物院「夜巡牌」3514×4609 五体文环绕＋中央虎纹、哈拉和林博物馆元代护照牌 5035×3734）都是**圆形**，属「异地同类」，**不得替换**。
7. **「教材用的是哪一幅」＝能否换的快捷判据**（2026-11-07）——若权威教材本身也只能用模糊拓片/低清图，说明该件**客观无高清本**，直接判 `保留-本底`，不必再找：实测元代「急递铺令牌」（原物流失境外，仅存羽田亨 1926 年《元代驿传图考》拓片，教科书沿用至今）、毛泽东「人民邮电」题词（原件藏中国电信博物馆，无公开高清）均属此类。

**近现代检索两条硬技巧（2026-11-07 实测）**：

1. **旧拼变体是头号杀手**——同一事件用汉语拼音查不到、用威妥玛拼写才命中：`Treaty of Nanjing signing` 返回马英九揭幕石碑，改 `Signing of the Treaty of Nanking` 立刻命中 2193×805 的历史画。常用对照：北京 Peking、南京 Nanking、广州 Canton、重庆 Chungking、延安 Yenan。
2. **三要素拼词**——「事件英文名 + 主体/年份」优于短语直译：`Hong Kong handover ceremony 1997`（拿到金紫荆广场 2400×1469）优于 `Handover of Hong Kong 1997`（返回维园集会照）。

**换图落地（保持规范）**：选定图存为 `{题号}_{n}.{ext}` → 同目录 `images/`；正文引用一律 `![](images/…)` 相对路径；被替换的原图移入 `{vault}/.trash/<原相对路径>`；改完跑 `scan_questions.py` + `fix_image_formats.py` 复检。⚠ **换图后必须复核题干与解析**——低质图糊掉/丢掉的器物细节有时正是考点，换了清晰图答案未必仍成立。

**反面案例（2026-10-09 实测）**：Obsidian 直接粘贴会产生 `Pasted image 20261009071439.png` 这类无意义名 + `![[…|396]]` 形态，且常落错目录层级（会落进 `images/images/`），并留下无引用的孤儿图；另**换图要看内容不只看尺寸**——「人面鱼纹彩陶盆」换成网络斜视照（184×109）后纹样反而看不清，反不如原卷俯视图可用。
