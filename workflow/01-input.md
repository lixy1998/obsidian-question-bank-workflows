# 流程一 · 录入

> **触发词**：录入到题库、录入题目/试题、录入到 Obsidian 题库（用户说「录入到 Obsidian 题库」即默认启动本流程）。
>
> **前置检查**：运行前确认已初始化——`<skill>/scripts/skill_config.json` 含有效 vault 或 `TNOTE_VAULT` 已设；**若脚本报「未配置题库库」→ 先读 `workflow/00-init.md`** 完成配置再继续。

**按输入类型分流**（先判断源文件类型，再选链路）：

```
扫描版 PDF/图片 ───────────> 链路A：MinerU vlm ──> 全项 OCR 核对 ──┐
文字版文件（docx/md 等）───> 链路B：直读/脚本提取 ──> 轻量核对 ──┤
（PPT/pptx：先用外部工具转 docx 或 PDF，再走上面两条链路）        │
                                                                 ↓
                                        写 JSON ──> 查重预检 ──> gen ──> scan
                                                        │
                                    命中候选 ──> 用户裁定 ──> merge（并入主卷）／入库
```

## 链路A（扫描版 PDF/图片）

1. **MinerU vlm 解析**（仅扫描件需要；文字版文件走链路B 免 MinerU）：

   ```bash
   mineru-open-api extract "<文件或URL>" --model vlm -o "<输出目录>/" -f md
   ```
   - 支持 PDF/图片/Word/PPT/网页（**这是 MinerU 的能力**，非本 skill 内置）；`-o` 必须绝对路径正斜杠（Git Bash 的 /tmp/ 等会卡死）
   - 输出 `<文档名>.md` + `images/` 同级；Token 在 `~/.mineru/config.yaml`；无 token 时改用链路B

   **备选：`extract(vlm)` 不可用时改用 PaddleOCR MCP**（2026-10-03 立；**不再采用 MinerU flash 通道**）

   `extract(vlm)` 在**服务端拥塞或队列故障**时会整体失败——实测整份与拆分后均返回 `Error: timeout waiting for batch`，服务端任务恒停在 `pending`（调度器不取任务，非本地问题）。此前曾以 `flash-extract`（免 Token）兜底，但实测其**质量明显不足**：选项错序/被吞、第三方水印串入正文、方言与生僻字 OCR 失真、图片只有 `<!-- image -->` 占位、且限 10MB——须逐题回图复核才敢入库，成本高于收益。**故本流程不保留 flash 备选，vlm 不可用时一律改用 PaddleOCR MCP**：

   - **入参**：`input_data` 取**绝对路径**（亦支持 http(s) URL / base64）、PDF 必带 `file_type: "pdf"`、`output_mode` 取 `simple`（纯文本）或 `detailed`（JSON）、`return_images` 默认 true
   - **能力与质量（实测）**：支持 PDF 直传、不必逐页；题干/选项/答案/表格（转 HTML `<table>`）/图片位置**均准**——同一份卷 flash 出的选项错序、水印混入、OCR 错字，PaddleOCR 均正确
   - ⚠ **两条注意**：① 单次调用偶发 `Error calling tool`——**重试即可**（实测 3 份中 1 份需重试）；② 返回的 `<img src="imgs/…">` **不含图片二进制**，图片仍须另从原 PDF 裁剪（`pull_pdf_images.py` 或 pymupdf `get_pixmap(clip=…)`）
   - 文件过大时先按页拆分再逐份调用（`pymupdf: fitz.open().insert_pdf(from_page=…, to_page=…)`）
   - **通道取舍**：`extract(vlm)` 为首选（一次出 md + images/ 最省事）；其不可用时**一律改用 PaddleOCR MCP**

   **⚠ 教辅卷扫描件的源型识别（多卷合排，先确认再逐题核对）**

   教辅「期末复习·练真题」类资料常把各地期末卷**连续合排**成一本：正文每套卷各带卷头（如「试卷6 平顶山市」）与页脚，**答案册则是多套答案连排**。两点必须先确认：

   - **答案册按「试卷N」分节截取**：答案册一页常同时含相邻两套卷的内容（快速对答案表、难题易错题精解、非选择题答案各自成段），须按卷头标题切段，别把上一套的答案挂到下一套题上。
   - ⚠ **答案册与正文册的对应关系可能错位**：实测「平顶山卷答案.pdf」首栏实为**安阳卷**的非选择题答案——答案册按自身页码顺序装订，与正文册的卷序**不一致**。**判据**：拿答案与题干设问逐问对齐（如答案「图一：隋朝大运河 图二：明长城」须能在该卷材料中找到对应两图），对不上就翻前一/后一套的正文比对；**不按文件名的卷名硬认**。

2. **人工核对 OCR**（必做，逐项对照源文件，7 项清单）：

   | 检查项 | 案例 |
   |---|---|
   | 题号缺失/串号 | 2026 中考第 16 题被 OCR 成「6.」 |
   | 选项合行 | 「A. xxx B. xxx」挤一行需拆分 |
   | 表格识别 | 数据表转 markdown 表格 |
   | 图片引用 | `![](images/hash.jpg)` → 题库内重命名 `21_1.jpg` |
   | 材料标题缺失 | 2026 中考 23 题「材料二」标题未识别，据答案反推补上 |
   | 重复段落 | 24 题 (3) 设问重复一次，去重 |
   | 答案表 | 选择题答案表提取为 20 项映射 |

## 链路B（文字版文件：docx/md 等，免 MinerU）

有文字层、无需 OCR，核对降级；多来自第三方整理（zxls 等）或官方讲解件，须与官方扫描件交叉核对关键项；无扫描件时以文字版文件为唯一来源并在交付中注明。

1. **结构化提取**（按格式选方法）：
   - **docx**：`python scripts/read_docx.py "<试卷.docx>" -o <输出目录>` → 生成 `<docx名>.md`（题号/题干/选项/表格/【答案】，按文档原顺序）+ `images/`（内嵌图片）
   - **md/markdown**：直接读取正文（题号/题干/选项/表格已结构化），内嵌图片复制到 `images/`
   - **PPT/pptx**：⚠ **本 skill 不提供 pptx 提取脚本**（`read_docx.py` 只接 `.docx`），需自行处理——可先另存/导出为 docx 或 PDF 走上面两条链路，或自行写提取代码（`python-pptx` 的 `shape.has_text_frame` / `shape.has_table` 取文字、`shape.shape_type == PICTURE` 取 `shape.image.blob`），提取结果按本流程后续步骤入库。图片逐张与题号核对归属，讲解页的「知识卡片/解析」、卷头等非原卷图**不入库**（参考录入郑州二七区卷经验）
     - ⚠ **同目录另有「试卷讲解PPT」不构成障碍**：只要该卷同时有**扫描/拍照的正文件**（PDF/图片），直接走链路A 即可，**不必先处理 PPT**（2026-10-06 实测：安阳、平顶山两卷目录里同放「试卷N xxx.pptx」讲评件，正文扫描 PDF 照常走链路A 入库）。
     - ⚠ **「试卷讲解PPT」的图片须按定式改造**：其图片是**黑底幻灯片截图**（照片/图形与图注艺术字烘焙进同一张 PNG，无更干净的源），**不能直接入库**——先判原图底色（`mean>130` 即白底、**勿反相**），再分三类处理：**实物照片只刷背景**（整张反相会变负片）、**示意图整张标准反相**（禁用"抬黑反相"）、**纯文字图不保留图片**（文字搬进正文），**多图一律裁开**后用 md 表格「上图下文」重组。判据、代码与实测见 `references/参考-图片与图注修复.md` §六
   - 其它文字版格式（如 wps/odt）：先转成 docx 或 md 再走对应链路
2. **轻量核对**（4 项，替代 OCR 全项核对）：

   | 检查项 | 说明 |
   |---|---|
   | 答案表完整 | docx 自带【答案】，缺失/残缺时对照官方扫描件补 |
   | 题号连续 | 无串号、缺失 |
   | 图片补齐 | docx 图片常不完整（如选择题图片选项被吞成 "A.B.C.D."）；缺图用 `pull_pdf_images.py` 从官方 PDF 裁剪补图，并核对素材图片归属 |
   | 图片格式 | 入库后缀只能是 **jpg / jpeg / png / gif / webp / bmp / svg**——**TIFF/EMF/WMF 在 Obsidian 里不渲染**（2026-09-15 实测库里积了 12 个 tiff，全是破图）。`read_docx.py`、`pull_pdf_images.py` 已加格式守卫自动转 PNG；发现存量不可显示格式，用 `fix_image_formats.py` 巡检修复 |
   | 官方交叉核对 | 答案/朝代/课号/细节与官方扫描件比对；**冲突以官方扫描件为准**，差异在题库「解析」注明（针对题目本身存在问题的情况） |

   **源卷无答案时**（高考/等级考「无答案版」常见）：外部检索参考答案并**多源交叉验证**（权威序：官方公布答案 > 学科网/gaokao.cn 等正规教辅转载 > 第三方整理文档；选择题逐项比对，实测多源一致方可采用）。非官方来源的答案**末尾统一标注**「（参考答案源自网络流传之非官方答案，仅供教学参考）」，与库内 2026 河南高考卷体例保持一致；交付时向用户说明来源等级与复核建议。

   补图命令示例（先整页渲染定位，再按相对坐标裁剪）：
   ```bash
   python scripts/pull_pdf_images.py "<官方扫描.pdf>" --page 3 --rect "0.05,0.45,0.95,0.62" --out 6_1.jpg
   ```
   `--out` 后缀定格式：**文字/线稿用 `.png`（无损）、照片类用 `.jpg`（体积小 4~6 倍）**。写成 `.tiff` 会被脚本自动改存 `.png` 并提示——**别再用 tiff，Obsidian 不显示**。

   **题内素材图的裁剪定位（别目测试错）**

   `pull_pdf_images.py` 的 `--rect` 是**页面相对比例**；靠目测估比例要反复试错（实测裁贵州卷两幅并排示意图调了 5~6 轮才对齐）。**改用像素扫描定边界**——先按比例粗限区域（避开正文文字干扰），再统计每行/每列的黑像素数，命中即为图框线：

   ```python
   import fitz, numpy as np
   d = fitz.open(pdf); p = d[页索引]; w, h = p.rect.width, p.rect.height
   pix = p.get_pixmap(dpi=200, clip=fitz.Rect(0, h*0.40, w, h*0.66))   # 先粗限区域
   img = np.frombuffer(pix.samples, np.uint8).reshape(pix.height, pix.width, pix.n)
   g = img[:, :, :3].mean(axis=2)
   dark_col = (g < 128).sum(axis=0)   # 每列黑像素数 → 竖线：图框左右边 + 并排图的中缝
   dark_row = (g < 128).sum(axis=1)   # 每行黑像素数 → 横线：图框上下边
   ```

   - 取「黑像素数 > 区间高度 × 0.55」的列即竖线（**阈值 0.7 常落空，实测 0.55 才命中**）；行同理。
   - **并排多图会得到 4 条竖线**，两图各自边界一次算出（实测贵州卷第 5 题得 x=0.092／0.382／0.407／0.696）。
   - ⚠ **失灵回退判据**：**无边框、浅色、半色调**的图（照片、渐变、浅色表格）扫不出线——实测扫其水平线返回空。此时改看正文区块 bbox，或退回目测。

   **⚠ MinerU 的盲区：无边框示意图（时间轴 / 管辖脉络图）**（2026-10-06 实测）：这类图由**细线＋文字**构成（如「西汉—西域都护府 → 唐朝—安西和北庭都护府 → 元朝—北庭都元帅府 → 清朝—伊犁将军」），无图框、无底色，**MinerU vlm 不提图**，只在正文吐出一串乱序文本，甚至错拼成无意义的 HTML `<table>`（实测时间轴被识别成 `907｜916｜1038｜西夏｜1227｜1206`）。**判据**：正文出现「箭头＋年代＋机构名」的杂乱行。**处置**：回源 PDF 裁剪补图——本类属"无边框"型，像素扫描同样扫不出线，用**比例试裁 → `Read` 目视校验边界 → 微调**（线稿存 `.png`）即可，两三轮即准。实测两例：平顶山卷 18 题（新疆管辖脉络）、安阳卷 13 题（台湾管辖脉络）。
   - **两种方式共同的安全线**：裁完必须 Read 一遍确认图注与边缘要素未被切（阈值失灵时最容易切边）；批量时先扫描求比例 → 一次性裁 → 拼编号网格图核对归属（拼图方法见 `references/参考-图片与图注修复.md`）。

3. 余下与链路A相同：写 JSON → gen → scan

## 写题库 JSON（两链路共用）

每道题一条记录，字段规范见 `references/fields.md`（含卷名命名约定、类别枚举、JSON 模板、**多值录入判据**）；**教材映射用各册别词表课号**（查 BOOK_INDEX——初中：7上/7下 2024 版节、8上/8下 2025 版节、9上/9下 2026 版节；高中：纲要上/下、选必1~3 依教材目录整节收录，**选修1/选修2 官方无教材、依课标选修课程的 7 个专题**，课名形如 `专题2.2 文献史料研读`）

**定位三字段（册别/单元/课）多值优先**——逐题三问定值：①设问**直接考**的课＝首项（命题落点）；②材料/情境/选项**还落在**的课依次作兼涉项（**不设项数上限**，按实际涉及写全）；③跨册则写全册别。三项同序平铺，兼涉项须能在材料或设问中可指认。判据、防滥约束与三口径检索见 `references/fields.md`「多值字段说明」

**生成 + 校验**（两链路共用）：

```bash
python gen_problem.py 卷_选择题.json
python gen_problem.py 卷_非选择题.json
python scan_questions.py --卷 <卷名>   # 「✓ 无问题」才交付；同时看有无 ℹ 定位字段提示（多值漏写）
```

**批量回填题干/选项（链路B 三步走）**：`read_docx.py`（或 MinerU）先得到源 md → **`import_from_md.py` 按题号批量回填「题干」「选项」进录入 JSON** → 再逐题补字段与解析。回填脚本自动完成四件事（都是实测踩过的坑）：

```bash
python scripts/import_from_md.py --源 <提取出的 md> --json <录入 JSON> [--skip 7,18]
```

- **剔除卷首「注意事项」段**——其「1. 2. 3.」编号行会被题号正则认成第 1~3 题并覆盖真题块；
- **截断答案区**——「此资料来源于 / 历史试题参考答案 / 【答案与解析】/ 参考答案」与紧凑答案行（`1-5:BABDA`）取最靠前者截断；
- **切选项**——A–D 两项紧邻、字母后无空格（`理性C.人物…`）都能切；切不足 4 项会告警；
- **规范图片引用**——按题号改成 `images/{题号}_{n}.{ext}`，**保留原扩展名**。

> 该脚本只改写 JSON 的「题干」「选项」两字段；JSON 其余字段、结构一律不动。`--skip` 用于源卷残缺、题干需手写的题（如源 docx 缺第 18 题时 `--skip 18`）。

**模板使用**（Obsidian 内手工录入，零散补充；批量走 JSON）：`<skill>/templates/历史试题模板.md`（初始化时已复制到 `{vault}/0-Template-模板/`）—— Templater 新建单题，填 YAML + 正文，删注释块。正文规范：**只删原卷题号与整题分值，题干（含作答要求引导语）与小问分值全保留**（细则见 `references/fields.md`「正文题号与分值规范」）。

## 查重与合并（一题多卷，v1.3.0 起）

**入库前必查重**——同一道题常被多卷收录（"中考真题被期末卷/模拟卷原样收录"最常见）：

```bash
python dedupe_questions.py --check <卷_选择题.json>     # 写 JSON 后、gen 之前跑：逐题返回库内疑似 Top-3
```

- **无命中** → 照常 `gen_problem.py` 入库
- **有命中** → 出候选（级别 + 相似度 + 差异点）→ **裁定**：
  - 判为**同题** → 别名题不再重复存；把本卷 id 并入库内主题：
    ```bash
    python dedupe_questions.py --merge <库内主题.md> --with <本卷该题入库后的 md> --apply
    ```
    （合并会把本卷 id/来源追加到主题、把本卷该题归档）
  - 判为**不同题**（材料同设问不同 / 部分小问重合）→ 照常入库，互不合并
- 判定边界与流水线（L1 精确 / L1' 选项集合 / L2 相似度 / L3 预筛 / L4 AI / L5 用户）见 `references/fields.md`「一题多卷与去重」——**阈值只用来缩小人工面，不单独下结论**

**定期全库查重**：批量录入后跑 `--scan` 出《疑似重复清单》→ 裁定 → `--merge`。

**安全线**：别名题移入 `{vault}/.trash/<原相对路径>`（＝库内 Obsidian 回收站，不删除、可在回收站面板还原到原位）；日志 `{vault}/.dedupe/YYYY-MM-DD.json` 支持 `--rollback`；别名卷留 `_重复题清单.md` 供还原。

**合并后必看自检**：脚本写盘后自动解析主题 frontmatter，输出 `[自检] 主题 frontmatter 解析正常：id=[…]`；若出现 `❌ 主题 frontmatter 校验失败`（此时别名**尚未归档**），手工修正该文件后重试即可，不会留下半成品。
**批量合并**：逐对跑 `--merge --apply`，每对确认自检行；全部完成后 `scan_questions.py`（应「✓ 无问题」）+ `--list-merged`（核对 id 多值）复核。

**合并后同步引用（方案一，2026-09-21 定案）**：题目被合并归档后，此前引用过它的 `3-试题研究/` 报告会**静默断链**——Obsidian 不报错，且库里同名文件极多（`25.md` 十余个），模糊匹配可能把链接带到另一道无关题上。处置＝把失效引用**改指主卷**（旧题身份以 id 形式活在主卷上，故不引归档区）：

```bash
python scripts/check_note_links.py                 # 巡检 3-试题研究/（只读）
python scripts/check_note_links.py --fix           # 出修复计划（仍不改盘）
python scripts/check_note_links.py --fix --apply   # 执行（记日志 {vault}/.linkfix/，可 --rollback）
python scripts/check_note_links.py --cite <题目id>  # 合并前预检：谁引用了这道题
```

- 同时检出**指向库内回收站 `.trash/` 的引用**（文件在，但 Obsidian 不索引该目录＝已断链）一并改指主卷；不可定位者单独列出待人工确认，**不猜测**
- 别名默认**保留原样**（只换路径）；改用主卷 id 作别名加 `--alias theme`；表格内 `\|` 转义风格原样保持
- **批量录入后偶发**：源卷被陆续录入时，早先报告引用的题可能被后来的卷撞题合并 → 定期（如每批录入收尾）跑一次无参巡检即可

## 铁律（录入专属）

1. **答案/解析只进 YAML frontmatter，正文只放题干+选项/材料**——学生卷安全由此保证
2. **课名必须过 BOOK_INDEX**：初中按册别映射版本节校验——7上/7下→2024版节、8上/8下→2025版节、9上/9下→2026版节（按教材首印定版年份；后续小修订不建新版词表，就地修订并联动，见 `references/book_index.md`「修订联动」）；**高中各册整节收录**——纲要上/下、选必1~3 依教材目录，**选修1（史学入门）/选修2（史料研读）官方未编写教材，依课标选修课程【内容要求】的 7 个专题**（册别写 `选修1`/`选修2`、课名写 `专题X.Y <专题名>`，单元写模块名），录入与 scan 自动比对
3. **素养标注以题为原则，不追求全覆盖，但字段必须完整创建**：核心素养/素养层次水平/关键能力按题判断、均可多值标注，但**一套卷不追求 A1-C3 全要素覆盖**（三字段非必填，scan 不强制）；题目不符合某字段内涵（如纯识记题不涉史料实证）则该字段**留空不标**
4. **正文题号与分值规范**：正文删原卷题号（id 已含题号）与整题分值（YAML「分值」已有），保留作答要求引导语、各小问分值，以及**选择题题干末尾的作答括号「（　　）」（全角括号＋两个全角空格，不删不改半角）**；细则见 `references/fields.md`「正文题号与分值规范」
5. **先查重后入库**：新题入库前必须跑 `dedupe_questions.py --check`；命中候选须经用户裁定——判为同题则并入库内主卷（别名不重复存），判为不同题才入库。**禁止手工删题**：合并/归档/回滚一律走脚本，否则无日志、不可回滚、无卷内清单
6. **定位三字段「多值优先，首项＝命题落点」**（v1.5.0）：`册别/单元/课` 不是「挑一个最贴的课」，而是**标全所有涉及的课**——首项放设问直接考查的课，其后依次为兼涉课（背景/参照/结论落点），**不设项数上限**，三项同序平铺；兼涉项必须能在材料或设问中可指认。录入后 `scan_questions.py` 会比对「课的所属单元/册别是否写进本题字段」，命中即输出 `ℹ 定位字段提示`——**逐条补齐再交付**

## 陷阱（录入专属）

1. **YAML 特殊字符**（英文引号/冒号/方括号）须转义——`_yaml_scalar` 已处理；手写 JSON 注意
2. **材料题图片**：JSON `图片` 字段 `[{"src": 源路径, "name": "21_1.jpg"}]`，正文引用 `![](images/21_1.jpg)`；生成自动复制入库。⚠ `name` 的后缀只能是 Obsidian 可显示格式（jpg/jpeg/png/gif/webp/bmp/svg），**绝不写 .tiff**——显示不出来（2026-09-15 已全库清理过一次）。**选格式依据**：连续调扫描件/照片存 **JPG**（PNG 反而大数倍）；只有**真透明**（alpha 存在非 255 像素）或**颜色数 ≤16 的二值/图表**才留 PNG（⚠ TIFF 是 4 通道 ≠ 有透明）。**源头守卫**：`read_docx.py`（docx 内嵌图）与 `pull_pdf_images.py`（按 `--out` 后缀决定格式）均已加**格式守卫**，非白名单自动转 PNG；存量图片的巡检与批量转换属流程三（`workflow/03-check.md`「图片格式体检」）
3. **第三方整理冲突**：docx 多来自 zxls 等第三方，答案/细节可能与官方扫描件不符。**冲突以官方扫描件为准**，差异在「解析」字段注明（针对题目本身存在问题的情况），不静默采用
4. **选择题 JSON 三件套缺一不可**（2026-09-14 血泪）：手写 JSON 时只顾着写「解析」「答案」而漏掉「题干」「选项」→ 生成的选择题文件正文为空，`scan` 报 `[正文为空]`（2025 河南高考一次中招 13 题）。**写完 JSON 必须自检字段**：选择题＝题干＋选项（4 项）＋答案；材料题＝题干（含材料与设问）＋答案。批量录入可从提取的 md 回填：题干取原卷 `^N．(.+)$` 行（去题号；**末尾作答括号保留并统一为「（　　）」**），选项在题号段内按 `(?=[ABCD]．)` 切分凑齐 4 项
5. **题干忠于原卷，一字不改**（2026-09-14）：①**引号必须查码点，不能看屏幕**——终端/日志会把中文弯引号 “ ”（U+201C/201D）渲染成直引号，肉眼无法分辨，误判后会写成「」或 `"`；规则是**题干与材料一律用原卷的引号形式**，只有题库自撰文本（解析、备注）才用「」。②**不替原卷补漏**：原卷自身的疏漏（分条末尾漏分号、标点不统一等）不改动，题库是史料载体、忠实优先，必要时在「解析」注明。③录入后写一次性脚本逐题与原卷归一化比对（去图片引用、去题号、全角转半角、去空白）确认零差异
6. **选择题图片的位置靠题干手写引用**（2026-09-14）：`build_body` 默认把「图片」字段追加到**正文末尾**（选择题会落到选项之后）；要置于题干与选项之间，须在题干里手写 `![](images/xx)`——同名引用会被自动去重，不会重复插图
7. **解析册类 PDF（原题+解析混排）的栏目图标会被提成大量小图**（2026-09-16 河北卷实测，34 页出 101 张图）：此类解析册每题由「试卷原题 / 参考答案 / 考查目标 / 试题分析 / 试题亮点」五栏构成，MinerU 会把每个栏目名前的**小图标**各提成一张约 55×57、1~1.6KB 的图——101 张里 95 张是图标。**判据：边长 ≲120px 或体积 <5KB 的图一律视为栏目装饰，不入库**（真素材图如器物照、版画、漫画、示意图体积都在 17KB 以上）。同一文档中的**表格截图**（表 1/表 2/表 3）也会被单独提出，与已转出的 HTML `<table>` 重复——**表格一律用 HTML table 入题干，表格图不入库**
8. **选项行是 OCR 重灾区**（同上实测）：①两列排版选项常被并成一行（`A. … B. …`）；②多列错位时可能整体乱序（河北卷 5 题被识别成 A、C、B、D，且把图注「图2 元磁州窑西游记图枕」并进 C 行）；③题干末句会与选项粘连（`该版画体现了，当时A. …`）。**逐题核对：选项 4 项齐、顺序 A→D、无题干/图注混入**
9. **疑字须渲染放大复核，不能只看 MinerU 文本**：形近字是解析册 OCR 的主要残留错误（实测「拂菻」→「拂秣」/「拂获」、「供馌」→「供饙」）。用 `pymupdf` 按**页面比例**裁剪 300~500 dpi 条带再读图确认（`clip=Rect(w*x0, h*y0, w*x1, h*y1)`）——⚠ 比例要按 **pdf 页面**算，别按渲染 png 目测（目测会偏，白裁几轮）
10. **录入后跑归一化回归自检**：`python scripts/verify_against_source.py --源 <MinerU导出.md> --卷 <卷名> [--忽略 03,04]`——逐题比对入库正文与源文本，输出相似度与差异片段；**差异只应出现在题号/图注表号/刻意修正的 OCR 错字**（选项前缀 `(A)`↔`A.` 已在归一化中抹平，正确切分见脚本内注释：`## 材料` 属题目内部标题，不可当块结束）。已声明差异用 `--忽略` 标注，退出码 1 可作流水线阻断
    - ⚠ **已知局限：题干块会被答案区题号覆盖**（2026-09-16 实测，**不是入库错误**）：源 md 为「原卷 + 答案同文件」时，`split_source()` 的 `^(\d{1,2})[.．]\s*(.*)$` 会把答案区的行首题号也认成新块起始，**覆盖前面真正的题干块** → 该题相似度暴跌（实测 2024洛阳涧西区一模 21~24 题 0.06~0.14、2024中原名校联盟 01/02 题 0.02）。触发形态有二：① 答案表整行连排「1.B 2.D 3.C…」（`\s*` 允许零空格，故「1.B」被判成题号 1）；② OCR 错号「2.4.」被判成题号 2。**判据**：相似度极低、且差异片段显示**源侧内容是答案文本**（如 `源[(1)都是为]`、`源[B2.D3.C…]`）时即为此局限，直接 `--忽略` 该题号；题干正确性仍以人工对照原卷为最终依据，不要在脚本侧改判
11. **解析册常不印分值**：卷面总分、各题分值、小问分值都可能缺失 → YAML「分值」按本省卷面结构推定并**在交付时声明依据与待核**，**不臆造小问分值**
12. **MinerU 的图片归属必须目视核对，不能只看引用位置**（2026-09-16 三卷实测）：
    - **图片会被排到相邻题下**：2023洛阳涧西区一模的「仁义自成」瓦当图被 MinerU 排在**第 5 题**的图片位置，实为**第 4 题**配图；按引用位置入库会把图挂到错的题上
    - **含图表格会被整体提成图片**：表格材料（单元格内嵌货币图、人物肖像等）整表被提为一张图，与题干文字重复。**处置**：**表格截图不入库**；单元格里的真素材图（货币、肖像等）单独按 `{题号}_{序号}.jpg` 入库。⚠ **重建只能用 md 表格（管道式），不可用 HTML `<table>`**——Obsidian **不解析 HTML 块内的 md 图片语法**，写在 `<td>` 里的 `![](images/…)` 一律不渲染（2026-09-23 实测：省实验二模第 1 题，HTML 表格版三张图全不显示）；而 **md 表格单元格是原生行内语法环境，`![]()` 与换行 `<br>` 都正常渲染**（库内既有先例：`郑州市经开区2024-2025学年7上期末_选择题/01.md` 四图横排、`2-命题与评价/初高中历史课程标准·学业质量.md` 表格内多行 `<br>`）。✅ **多图题统一写法（2026-09-26 用户裁定，硬规定）**：一律用 md 表格横排——**第一行图片、第二行图注**，逐列对齐；**不写**连续 `![]()` 段落 + 一行图注的排法，也不用 `<br>` 把图注塞进图片格：
      ```markdown
      | ![](images/1_1.jpg) | ![](images/1_2.jpg) | ![](images/1_3.jpg) |
      |:---:|:---:|:---:|
      | 二里头遗址出土的陶甑 | 殷墟出土的“好”汽柱甑形青铜器 | 信阳息县出土的宋金时期六耳铁釜 |
      ```
      适用**所有多图题**（选择题图组、材料题材料图解）；**单图题不用表格**，正文 `![](images/xx.jpg)` + 图注独立成行即可（库内先例：`郑州市经开区2024-2025学年7上期末_选择题/01.md`）。列序按**卷面阅读顺序**（左→右、上→下）。仅当表格严重挤压版面时才退回「一行一类」的图组式排版，如
      `植物纹：![](images/01_1.jpg) 花瓣纹彩陶盆　河南庙底沟出土`（名称与出土地之间可用全角空格分隔）。⚠ 单元格内**不写 wikilink 的 `|尺寸`**（`|` 会被当列分隔符吞掉，须转义 `\|`）——图片尺寸交给主题 CSS 或统一样式。版式重构若改变指代（原表「左图」），在**「解析」字段注明**。**无图的纯文字表格**两种写法（md 表格 / HTML `<table>`）皆可
    - ⚠ **原卷表格本就无表头时，不得自加表头**（2026-09-26 实测）：如「第1集/第2集/第3集」这类两列表，用 HTML `<table>` 忠实照录——自加「集数|内容」表头会被回归自检判为越界（新乡卷题 12 相似度 0.94 → 改后 1.00）。**含图表格必须用 md 表格**（见上条），纯文字表格才可用 HTML `<table>`
    - **孤儿图先鉴别再定去留**：正文未引用的图片多为答案区表格截图（选择题答案表、评分标准、题干表格），一律不入库。⚠ 旧的「边长 ≲120px 或体积 <5KB 判为栏目装饰」判据**不足以覆盖**——本次孤儿图体积 35~214KB，也全是表格截图，须看图确认
    - **核对方法（快）**：把待核图片拼成编号网格图（PIL 拼图 + 序号标注）一次读出全部内容，再对照渲染页面确定归属，比逐张 Read 快得多
    - **图片选项题**（选项本身是图，如「下列甲骨文中‘兔’字是」）：`选项` 字段直接放图片引用 `![](images/2_1.jpg)`，图片同时写入 `图片` 字段供复制（正文已有同名引用，不会重复追加）——**写法与渲染（出 md 表格）见陷阱 17**

13. **答案区标题与卷首标题同名 → 截断须取「末次」出现**（2026-09-23 开封卷实测）：该卷第 1 行即 `# 九年级调研检测 历史试卷`，答案区又有 `# 九年级调研检测`——按 `find` 取**首次**出现（索引 0）时截断失败，答案区文本被当成题干入库（实测 4 道非选择题全中，正文成了参考答案）。**处置**：截断 marker 一律取**末次**出现（`rfind`）。**同类风险**：同一题号在试卷区与答案区各出现一次，按 `{题号: 块}` 建字典时若后者覆盖前者，入库的就是**答案文本**——切块须**保留首次出现的块**（试卷区在答案区之前）。
14. **题号可能被 MinerU 识别成 markdown 标题**：实测出现 `## 27.(6分)阅读下列材料…`。切块正则须容许标题前缀——`^[ \t]*(?:#{1,6}[ \t]*)?(\d{1,2})[.．]`，否则**该题整块丢失**（实测漏掉 1 题，`gen` 时只报「缺块」）。
15. **微信引流广告行常与最后一个选项同行**：形如 `… D. xxx 关注微信公众号「金榜六月」，获取更多优质备考试卷`——**按行删除会把该选项一起吞掉**（实测开封卷第 14 题选项 D 丢失）。**处置**：从「关注微信公众号」处**截断**该块，而不是删整行。
16. **选项字母后可能无空格，相邻选项之间也可能无空格**：`A.《几何原本》的出版`（字母后紧跟书名号）、`B.崇尚智慧与理性C.人物雕刻艺术近乎完美`（两项紧邻）。选项**起始匹配与切分**的 lookahead 都不能要求空白，用 `(?=[^\s])`；循环切分时**不要再加** `(?<=\s)` 前置条件（加了会把「理性C.」中的 C 漏掉，实测该题少一项）。⚠ 反面代价：题干中若出现「A.」样式（英文缩写等）可能误切——用**选项数自检**兜住（≠4 即回查原文）。
17. **图片选项题**（选项本身是图，如「下列文明成果属于古代埃及的是」四图选一）：`选项` 字段写成 `![](images/01_1.jpg) 金字塔` 形态（图 + 选项文字；选项只有图、无文字时只写 `![](images/01_1.jpg)`）；`图片` 字段仍要写全，供 gen 复制入库（正文已有同名引用，不会重复追加）。
    - **渲染走 md 表格**（2026-10-06 用户裁定，硬规定）：`build_body` 检出选项项含图片引用即**改出表格**——第一行图片、第二行 `A. 文字`（纯图选项写 `A.`），与 §10.2.1「多图题统一写法」同源（见 `references/试卷排版规范.md` §10.2.1）。⚠ **不要**再写成 `(A) ![](…)  (B) ![](…)` 行内拼接：会把数张大图挤进一段、图注被拆到各图下方，预览极乱；库内存量按此形态的旧题须重排。
    - ⚠ **没有 `图片位置` 字段**：图片出现在正文的什么位置，只由「题干手写 `![](images/…)`」与「选项内引用」决定，脚本不读任何"位置开关"。
18. **批量录入建议「两段式」**：先用一次性脚本解析 MinerU 的 md 得到**题干/选项**（自动），再由人工逐题补**字段与解析**（册别/单元/课/素养/难度/分值/答案/解析），最后 `dedupe --check` → `gen --force` → `scan` → `verify_against_source`。本节的 13~17 条都是**解析段**的坑——入库后 `scan` 只能查到「正文为空/定位字段缺项」，**选项少项、题干串了答案区这类错误 scan 查不出**，必须靠**选项数自检（≠4 回查）+ 回归自检（相似度骤低即回查）**双兜底。

19. **卷首「注意事项」的编号行会被误认成题号**（2026-09-30 实测）：`1. 考生领到答题卡后…` 这类说明行满足 `^\d+[.．]`，按「首次出现建块」时会**顶掉真正的第 1~3 题**（云南卷实测 3 题全中）。处置＝切块前先删「注意事项」段（到其后第一个「一、/二、」节标题为止）——`scripts/import_from_md.py` 已内置；手工处理时务必核对第 1~3 题题干是否成了说明文字。
20. **YAML 列表字段改写：两种风格并存、末尾必须保留换行**（2026-09-30 实测）：存量题库的 list 字段既有**块状**（`key:` 换行后顶格 `- 值`）也有**流式**（`key: [值]`）写法；脚本改写时必须按原风格渲染、并完整吞掉旧值（**含顶格 `- ` 行**，只吞缩进行会残留成游离项直接破坏 YAML），写盘后自检。
    - **先探测风格**：`^册别: \[` 命中＝流式；`^册别:\s*\n[ \t]*- ` 命中＝块状。**同一批题可能混风格**，须逐文件探测、不可整批假定
    - **块状缩进不一定是顶格**：不能写死顶格——吞旧值的正则用 `[ \t]*- `、渲染时沿用探测到的缩进
    - **吞旧值正则**（两式并列尝试，命中即替换，末尾统一补 `\n`，**不要再多加一个**否则产生空行）：`^{key}: \[[^\]]*\]\s*\n` ｜ `^{key}:\s*\n(?:[ \t]*- [^\n]*\n?)*`
    - **末尾必须保留换行**：替换区间 `(start, end)` 已含最后一个 `- 值\n`，渲染时若 `rstrip('\n')`，**下一字段名会被吸附到末项上**（`- 9下册别:`），YAML 解析成 dict → `scan_questions.py` 直接崩（`'dict' object has no attribute 'startswith'`）
    - **校验判据**：`单元` 在同单元多课时会去重，**项数常少于 `课`**；正确判据是「每课所属单元出现在 `单元` 列表」，判两者等长会出大量假阳性（项数一致性由 `scan_questions.py` 的配对提示单独给出）。`小节` 保留重复（一课多子目），项数可多于 `课`
    - **批量增删改字段一律用 `scripts/edit_fields.py`**（内置 YAML 类型复检 + 默认 dry-run + 备份），不要手写正则替换
    - **改完必做三重验证**：YAML 可解析（且点名字段确为字符串列表）+ 正文与备份逐字节比对零改动 + `scan_questions.py` 零报错

21. **md 表格渲染有两条硬约束，不满足就塌成纯文字**（2026-10-02 实测，Obsidian 1.13.7；库内曾积 13 处缺空行 + 10 处引用块内表格）。两条根因完全不同，须分别处置：

    | 症状 | 根因 | 修法 |
    |---|---|---|
    | 表格显示为裸竖线文本 | **表格首行与上一行之间缺空行**——md 表格必须空行隔断，否则整段被当普通段落吞掉（实测 DOM：整段塌成单个 `<p>`，无 table） | 在表格首行前**补一个空行** |
    | 引用块里的表格显示为裸竖线文本 | **Obsidian 渲染器不支持引用块内渲染表格**——`> \| a \| b \|` 在 **Live Preview 与阅读模式下都塌**（实测该引用块 children 全是 `P`）；换成 HTML `<table>` 无空格问题也塌 | 把引用块内 md 表格**整块替换为单行 HTML `<table>`**（保留 `> ` 前缀），两模式均实测正常（rows=5） |

    - 一键修复：`python scripts/fix_table_render.py [--apply] [--only blank|quote]`——默认 dry-run，`--apply` 逐文件备份为 `.bak-tblfix`；两类可分开修
    - ⚠ **引用块内 HTML 表格的副作用**：`<table>` 内不能写 md 语法——若表格单元格里有 wikilink 或 `![]()` 图片，转 HTML 后**会失效**。转前先确认单元格是纯文本；含链/图的表格须改用「移出引用块」方案（把材料从 `>` 引用降为普通段落）
    - ✅ **首选方案（2026-10-02 起，报告类文档）**：与其把表格转 HTML，不如**直接去掉引用符**——报告真题的标题行已用加粗给出出处，引用块本属冗余。去掉 `>` 后表格自然回落为 md 表格，单元格可正常嵌链嵌图。一键改造：`python scripts/fix_quote_to_plain.py --dir "3-试题研究" [--apply]`（默认 dry-run，逐文件备份 `.bak-unquote`）；规范见 `workflow/04-angle-analysis.md §6c`。`fix_table_render.py --only quote` 仅保留给**必须留在引用块内**的场景（如卷首元信息块内的表格）
    - ⚠ **与「HTML 表格内嵌 md 图片」是两条不同限制**，勿混：那条是「`<td>` 里写 `![]()` 不渲染」（见第 12 条第 2 点），本条是「引用块里写表格不渲染」
    - 自检口径：`fix_table_render.py`／`fix_quote_to_plain.py` 复检均应报 **0 处**；人工核验用浏览器的 `querySelectorAll('table')` **数不出引用块内的表**（懒渲染 + 结构差异），判据要看 `blockquote` 的 `children` 里是否含 `TABLE`
