# 流程三 · 校验与词表维护

> **触发词**：题库质量检查、校验、scan。
>
> **前置检查**：运行前确认已初始化——`<skill>/scripts/skill_config.json` 含有效 vault 或 `TNOTE_VAULT` 已设；**若脚本报「未配置题库库」→ 先读 `workflow/00-init.md`** 完成配置再继续。

## 校验

`python scan_questions.py`（必填字段/id 唯一/枚举/课名词表/正文非空 + **frontmatter YAML 解析失败单列**（带「第 N 行第 M 列」定位；该文件跳过其余校验、不计入题目总数）+ **关键能力要素名白名单校验**（编号格式合法、但要素名不在郑林 9 要素内 → **问题级阻断**；只卡编号正则 `^[ABC][1-3]-` 会留盲区）+ 统计；**关键能力旧格式为提示级**——存量徐奉先 3×3 标注迁移未完成时输出 `ℹ` 提示，不计入「✓ 无问题」；**定位字段与多值配对为提示级**，见下）；`--json` 机器可读（退出码与文本模式一致阻断）

- **退出码**：有问题 → **1**（可阻断流水线）；`✓ 无问题` → 0。`ℹ` 提示级（关键能力旧格式、定位字段、多值配对）**不阻断**
- **定位字段提示**：逐题比对 `课` 与 `单元/册别`——课的所属单元/册别（据 BOOK_INDEX 层级解析，初中取目标版本节 + 高中各册节〔含选修1/选修2〕）未出现在本题字段中即提示。**多值录入的兜底网**：单值题不会触发，跨课/跨册综合题漏写单元或册别才会命中。提示级不阻断交付，但**须逐条补齐**（补的是真实疏漏）
- **多值配对提示**：`册别/单元/课` 三项按「同序平铺」录入，但机器只校验其中可判的两处硬伤——① **单元项数多于课项数**（多出的单元没有任何课承接）；② **册别有重复项**（同册重复声明，如 `[8上, 8上, 8上]`）。
  - **刻意不报的两类写法自由**（报了就是海量假阳性）：单元列表**允许**多于课（单元卷/跨册题常把上级单元一并写入）、单元顺序**允许**与课不同序、单元在同单元多课时去重后项数必然少于课
  - 判据来自 BOOK_INDEX 层级：每课在其声明册别下的所属单元，与本题 `单元` 列表逐项比对

- **id 多值校验**：id 为 list 时逐项查重（含列表内自重复）；并做**一题多卷交叉校验**——别名 id（第 2 项起）若仍作为独立题存在于库中，报 `[别名未归档]`（提示该跑 `dedupe_questions.py --merge`）
- **学史方法课名**（教材单元层级，2026-10-06 起）：`课` 写方法条目本身（如 `如何从出土文物中获取信息`），只校验方法名是否在 BOOK_INDEX「初中·学史方法（全六册）」表内（**不校验册别**；中高考题常按「史事 + 方法维度」跨册标注）；`单元` 应含 `学史方法`；旧前缀写法 `学史方法-<方法名>` 兼容存量
- 输出中的「一题多卷：N 题含别名 id」为信息行，非问题

## 图片格式体检

```bash
python fix_image_formats.py                  # 只读巡检：列出 Obsidian 不显示的图片（默认不动文件）
python fix_image_formats.py --fix            # 出修复计划（dry-run）
python fix_image_formats.py --fix --apply    # 执行：转换 → 同步改引用 → 复检 → 原图入回收站
```

- 其他参数：`--keep-original` 转换后保留原图（默认入回收站）；`--backup <目录>` 自定义备份目录（默认 `<库同级>/_imgfix_backup_<时间戳>`）；`--vault <路径>` 临时指定其他题库库巡检（默认读 skill_config.json）
- **Obsidian 不渲染 TIFF/EMF/WMF**，库里存了就是破图；**批量录入后建议顺手跑一次巡检**
- 新图入库前已由 `read_docx.py` / `pull_pdf_images.py` 的**格式守卫**挡住（非白名单自动转 PNG），本命令管的是**存量**
- 判据：真透明或颜色数 ≤16 → PNG；其余（连续调扫描件/照片）→ JPG。⚠ TIFF 是 4 通道 ≠ 有透明
- 转换后必看脚本自带的「引用零断链」复检；原图走回收站、不直接删
- **引用形态＝出卷丢图第二根源**：五类非标准引用出卷时可能丢图——wk-bare `![[Pasted image x.png]]`（Obsidian 粘贴默认形态）/ wk-path `![[路径|尺寸]]` / md-alt `![说明](…)` / md-space 文件名含空格 / md-broken 断链。**录题时粘贴截图后必须检查引用形态**；存量用 `fix_image_formats.py --fix --apply` 批量规范化（含空格图自动改名、异位图移入同目录 images/；同名图不唯一、多目录共用自动转人工，勿手工绕过安全检查）。`export_student_paper.py` 自身已多形态兼容（识别五类引用即打包＋改写，缺图显式警告），但库侧规范化仍是渲染一致性与协作卫生的要求。⚠ **表格内的 wikilink 别名分隔符须写 `\|`**（如 `![[x.png\|300]]`），解析目标时先剥离反斜杠再取 `|` 前段——不剥离会把目标读成 `x.png\`，该引用被整体漏检
- **转换后三件事**：① 按**绝对路径**改引用（同名图可能转成不同格式，只按文件名会改错）；md 语法与 wikilink 都要改、wikilink 的 `|尺寸` 后缀保留；② 原图**移入回收站**不直接删；③ 复检「新图可读 + 引用零断链」
- **读图兜底**：个别 TIFF 的 IFD 会让 Pillow 报 `cannot identify image file`，文件其实完好——用 `cv2.imdecode(np.fromfile(p, np.uint8), IMREAD_UNCHANGED)` 可读（`np.fromfile` 同时绕开 cv2 不支持中文路径的问题）

## 图片质量体检（低质图筛查与网络补图）

```bash
python find_better_images.py --卷 <卷名>                                   # 只读：列出该卷低质图（附题号与图注）
python find_better_images.py --全库 --门槛 严格 --out <工作区>/低质图清单.md   # 全库严格档
python find_better_images.py --查 "应县木塔" --查 "Pagoda of Fogong Temple"   # 查候选（中英双轨）
python find_better_images.py --查表 检索词.txt --out <工作区>/候选清单.md      # 批量查
```

- **定位：只读辅助，绝不自动替换**——换图会改变题目的史料载体（图注指向特定器物），必须逐张人审
- **两档门槛**：严格＝边长 <150px 或 体积 <6KB（明显低质，优先处理）；宽松（默认）＝边长 <300px 或 <20KB
- **可替换范围**：文物/器物实物照片、历史地图、书影名画、人物肖像。⚠ **不要换**：原卷原创示意图/流程图、统计数据图表、带试卷版式水印的截图——命题者特制或原卷特有，网上没有对应
- **检索词＝图注**（脚本自动提取；多图表格取第 2 行同列图注）：**中英双轨、英文优先**——2026-10-09 实测 16 张，4 张可用高清图全由英文词命中，中文词大量返回无关 PDF/djvu
- **命中率实测（2026-10-09，16 张）**：严格可用约 25%、宽松约 44%。**著名文物/画作 → 高命中且高清；地方性文物、当代时政新闻图 → 基本无解**（Commons 覆盖不到），后者改走 WebSearch 定向找博物馆官网/百度百科
- ⚠ **同名不同物是最大风险**：同名检索会返回「同塔不同角度」「异地同类器物」（实测：禹州宋墓壁画 → 搜到的是登封的）。**候选必须人工确认是同一件**；确认不了就保留原图（换图看内容，不只看大小——实测「人面鱼纹彩陶盆」换成网络斜视照后纹样反而看不清）
- 两个技术坑：Commons 查询过密返回 **429**；本机 **SSL 握手超时**频发——脚本已内置 `--间隔`（默认 1.5s）与 `--重试`（默认 2）
- 换图落地：选定图存为 `{题号}_{n}.{ext}` 放同目录 `images/`；正文引用一律 `![](images/…)` 相对路径（**不要用 Obsidian 粘贴的 `![[Pasted image …]]`**，通用名全库歧义、且会被判非标准引用）；被替换的原图移入回收站；改完跑 `scan_questions.py` + `fix_image_formats.py` 复检

## 查重体检（建议每次批量录入后跑）

```bash
python dedupe_questions.py --scan --out <工作区>/疑似重复清单_YYYYMMDD.md   # 全库查重 → 候选清单
python dedupe_questions.py --list-merged                                   # 已合并题一览（id 多值）
```

- 命中候选 → 走 L4 AI 裁定 + L5 用户裁定（判定规则见 `references/fields.md`「一题多卷与去重」）
- 合并/回滚一律经 `dedupe_questions.py --merge / --rollback`（默认 dry-run，`--apply` 才写盘）
- ⚠ **禁止手工删除重复题**：手工删除不写日志、不更新别名 id、不留卷内清单，无法回滚也无法还原原卷

## 词表校准

scan 定位「课名词表」问题 → 写一次性映射脚本（`{字段}: {旧值}` 行替换）或对照 BOOK_INDEX 手动 Edit；反复场景写通用重映射脚本或直接 Edit md 的 YAML 字段

## 索引维护

`python gen_index.py`：从 BOOK_INDEX 生成 `1-MoC-索引/` 六册试题索引（含各册末 `## 学史方法` 单元节）＋ 高中七册索引（词表更新后重跑即可重建；`--dry-run` 预览、`--force` 覆盖手工标题保护）

## 铁律（校验专属）

1. **校验不过不交付**：录入/词表维护后必须跑 scan，输出「✓ 无问题」才可交付；「关键能力旧格式」的 `ℹ` 提示级问题不阻塞交付，但需标注待迁移

## 陷阱（校验专属）

1. **索引列由 gen_index.py 模板决定**：六个试题索引的 Dataview 列（`TABLE id AS 题号, 课, 知识点, 题型, 素养层次水平, 关键能力`）写死在 `gen_index.py` 的 `dv_query()`；**手工改索引文件会在下次重建时被覆盖**——要改索引列必须改脚本模板，不要只改生成后的 md 文件
2. **录入/组卷流程勿跑 gen_index.py**：索引为「混合式 MOC」（手工骨架 + Dataview 动态查询），新题 YAML 命中「课」字段即自动流入对应课，**录入新题、组卷出题均无需重建索引**；仅当 BOOK_INDEX 词表变化（新课加入/课名修订）时重跑重建
3. **定位字段提示不要当噪音忽略**：`ℹ 定位字段提示` 报的是真实漏写——多值录入时「写了课、忘了单元/册别」。**批量录入后必看此段并逐条补齐**；若某课名的单元在词表里就该命中而没命中，先查 BOOK_INDEX 单元名是否带注记（如「（完全重写）」这类行内注记会污染比对，须清理词表）
4. **多值配对提示的边界**：只报「单元多于课」「册别重复」两类硬伤；**单元少于课、单元与课不同序、同单元多课去重**都是允许写法，不报——**不要为了消提示而把合法的单元信息删掉**
5. **素养词表注记的孤立半符会跨行误吞正文**（写标签合规校验实现时必看）：`references/素养能力标签体系.md` 里任何「配对删除 `⟦…⟧` 及其内容」的实现，遇到不成对的左半标记会一路贪到下一个右半标记，**误吞整节正文**，使标签合规校验大批假阴性。
   - **词表标记全部成对**，可直接整体剔除（注意：此处**不写裸正则**——正则里必然含一个多余的右半标记，等于自己造坑）
   - **自己写规则/说明文字时不得出现裸半符**：引用符号就写「左半标记」，或在成对的 `⟦…⟧` 内说明
   - **自检判据**：校验脚本若报「标签大批不在词表」，先核 `re.sub` 前后的字数差是否≈注记总量；**差出数千字即为误吞**
